# 需要避免的结构

## "不仅...而且..."堆砌

过度使用这个结构是AI最明显的标志之一。什么都要加个"而且"，什么都要"不仅"。

| 模式 | 问题 |
|------|------|
| "不仅...而且..." | 什么都要加个"而且" |
| "不仅...更是..." | "更是"变成了口头禅 |
| "既...又..." | 强行凑两个属性 |
| "一方面...另一方面..." | 什么都要分两面说 |
| "与此同时，..." | 强行并列 |

**替代：** 选一个重点说。两个都重要就分开用两句话说。不要套公式。

## 排比句泛滥

三段式排比是AI的标配。读起来像口号，像领导讲话。

| 模式 | 问题 |
|------|------|
| "是...，是...，更是..." | 递进式排比 |
| "让我们...，让我们...，让我们..." | 煽动式排比 |
| "有...，有...，更有..." | 堆叠式排比 |
| "需要...，需要...，更需要..." | 号召式排比 |
| "从...到...，从...到..." | 对仗式排比 |
| "没有...就没有...也没有..." | 否定式排比 |

**替代：** 砍到只剩最重要的一句。如果确实要并列，用两项就够了。三项排比几乎永远是多余的。

## "不是...而是..." 及其变体

这是中文AI写作中出现频率最高的单一痕迹。AI几乎无法抗拒这个结构带来的"深刻感"，先否定一个说法，再提出"真正的"解释。一篇短文里出现3次以上就基本可以确认是AI写的。

所有变体：

| 模式 | 举例 |
|------|------|
| "不是X，而是Y" | "结果不是资源有效配置，而是通货膨胀" |
| "不在于X，而在于Y" | "关键原因不在于改革是否彻底，而在于它是否符合规律" |
| "并不是X，而是/还Y" | "市场经济并不是放开价格就能形成的，还依赖制度安排" |
| "没有X，而是Y" | "中国没有急于推翻旧制度，而是在维持稳定的前提下..." |
| "不是简单地X，而是Y" | "它不是简单地慢一点，而是让新制度逐渐生长" |
| "不是X的问题，是Y的问题" | "不是速度的问题，是顺序的问题" |
| "与其说X，不如说Y" | "与其说改革慢，不如说改革有策略" |
| "表面上是X，实际上是Y" | "表面上是速度问题，实际上是制度问题" |
| "看似X，实则Y" | "看似保守，实则务实" |

**为什么AI喜欢这个结构：** 它制造了一种"纠正误解"的戏剧感，让叙述者显得洞察深刻。但用多了就是套路。读者很快会发现每一段都在"不是...而是..."。

**替代：** 直接说Y。省掉"不是X"那半句，大部分时候读者根本没想过X，你不需要先否定它。

- "关键原因不在于改革是否更'彻底'，而在于它更符合制度变迁的经济规律" → "渐进式改革更符合制度变迁的经济规律"
- "结果不是资源有效配置，而是通货膨胀" → "结果是通货膨胀"
- "它不是简单地慢一点，而是让新制度逐渐生长" → "它在旧制度退出前先让新制度生长"

如果确实需要对比，用具体事实对比，不要用"不是...而是..."的句式模板。

## 其他假大空的对比

| 模式 | 问题 |
|------|------|
| "X的背后，是Y" | 假装深层揭秘 |
| "从X到Y的跨越/转变" | 假装有叙事弧线 |
| "不仅是一个X，更是一个Y" | 强行升华 |

**替代：** 直接说结论。"团队解决了问题"比"问题的背后，是团队日以继夜的努力"好。

## 空泛的总结段落

AI喜欢在结尾来一段升华，把前面说过的话再用大词重新说一遍。

| 模式 | 问题 |
|------|------|
| "总而言之，..." | 公式化总结 |
| "综上所述，..." | 论文式结尾 |
| "这让我们看到..." | 假装深刻 |
| "展望未来，..." | 空洞展望 |
| "站在新的起点上..." | 毫无意义的新起点 |
| "面向未来，我们..." | 假大空 |
| "相信在不久的将来..." | 毫无根据的乐观 |
| "让我们共同期待..." | 空洞的号召 |

**替代：** 用一个具体的观察或行动结尾。不说"总而言之"，直接说出结论。如果结论已经在正文中说过了，不需要再总结。

## 句尾拖曳的分析

陈述句后面挂半句空分析，是英文AI的"-ing"尾随短语翻进中文的形态。

| 模式 | 问题 |
|------|------|
| "……，体现了团队的智慧" | 空评价，删掉不损失信息 |
| "……，为后续发展奠定了基础" | 假因果。什么基础？ |
| "……，彰显了……的决心" | 宣传腔 |
| "……，标志着……迈出了重要一步" | 空泛升华 |

**替代：** 砍掉拖曳的那半句。分析真有内容就独立成句说清楚，没内容就不说。

## 被动句

每句话都需要有主语在做事情。被动句隐藏了执行者，削弱了力度。

| 模式 | 修改 |
|------|------|
| "被广泛认为" | 谁认为？说出来 |
| "得到了广泛的应用" | 谁在用？说出来 |
| "被称为..." | 谁这么叫的？ |
| "被视为..." | 谁这么看的？ |
| "问题得到了解决" | "团队解决了问题" |
| "被认为是最重要的" | 谁认为的？ |
| "受到了广泛关注" | 谁在关注？ |

**替代：** 找到执行者，放在句子前面。如果找不到具体的人，用"你"把读者拉进来。

## 无生命主语

给无生命的东西赋予人的动作。问题不会"得到解决"，文化不会"发生转变"，决定不会"浮出水面"。是人做了这些事。AI特别喜欢这种写法，因为它避免了说出具体是谁。

| 模式 | 修改 |
|------|------|
| "文化发生了转变" | 谁改变了行为？ |
| "行业迎来了变革" | 谁推动了变革？ |
| "问题得到了解决" | 谁解决的？ |
| "市场给出了回应" | 买家做了什么？ |
| "数据告诉我们" | 谁读了数据，得出了什么结论？ |
| "时代在召唤" | 没人在召唤，这是空话 |
| "历史证明" | 历史不证明，人从历史中得出结论 |
| "技术改变了生活" | 谁用技术做了什么？ |

**替代：** 说出具体的人。"团队改变了做法"比"文化发生了转变"好。没有具体的人就用"你"把读者拉进场景。

## 居高临下的旁白

飘在场景上面俯视，不把读者拉进来。

| 模式 | 问题 |
|------|------|
| "没有人刻意设计这一切" | 旁白视角 |
| "这背后是因为..." | 讲师口吻 |
| "人们往往会..." | 沙发社会学家 |
| "这告诉我们..." | 说教 |
| "人类社会..." | 宏大叙事 |
| "千百年来..." | 假装历史纵深 |

**替代：** 把读者拉进场景。"你不会坐下来决定要..."比"没有人刻意设计这一切"好。

## 自我指涉的元注释

正文里残留编辑过程的痕迹。读者要的是番茄炒蛋，端上来的却是"番茄炒蛋（无青椒版）"，旁边还贴着"这里没放青椒"的便签。

| 模式 | 问题 |
|------|------|
| "（无X版）""（已删除X）""（改）" | 变更注记混进成品 |
| "不打分""没用排比""这里不用破折号" | 宣告缺席。没人问，就不要解释自己没做什么 |
| "按照要求""如前所述""你说得对" | 正文在对反馈者喊话，而不是对读者说话 |

**替代：** 成品当成从零写的交付。要说明改动，写进单独的修改说明（见 SKILL.md 工作流），不进正文。直接写对的东西，不要宣布你不写什么。

## 数量宣告

先报数，再给内容。"两件事""三个原因""两行推导""一句话说清"都是这一类。

| 模式 | 问题 |
|------|------|
| "这个方案做两件事：……" | 数字是关于文本的元信息，读者自己会数 |
| "三个原因：……" | 宣告数量不增加内容，只增加仪式感 |
| "两行推导：……" / "一句话总结：……" | 预告篇幅。篇幅摆在那里，不用预告 |

**替代：** 删掉报数，直接说内容。顺序重要就编号，该几条就几条，枚举本身已经说明了数量。

**保留：** 数世界里的东西不是痕迹（"三个孩子""五公里"）。"十大误区"这类标题文体也算惯例。

## 句首问题

AI有一些固定的句首模式，反复出现就成了痕迹。

| 模式 | 修改 |
|------|------|
| 段落以"所以"开头 | 直接说内容 |
| 段落以"事实上"开头 | 砍掉 |
| 段落以"实际上"开头 | 砍掉 |
| 句子以"值得注意的是"开头 | 砍掉，直接说值得注意的事 |
| 句子以"需要指出的是"开头 | 砍掉，直接指出 |

## 节奏问题

| 模式 | 修改 |
|------|------|
| 三项并列 | 用两项或一项 |
| 自问自答 | 让问题独立存在，或者砍掉 |
| 每段结尾都是总结短句 | 变化结尾方式 |
| 连续短句堆叠 | 穿插长句 |
| 破折号/省略号过多 | 用逗号或句号 |
| "不总是。不完美。" | 把犹豫伪装成坦诚，直接砍掉 |

## 用词问题

| 模式 | 问题 |
|------|------|
| 偷懒的极端词（所有、永远、从不、每个人、没有人、一切） | 虚假的权威感。用具体的替代。 |
| 填充副词（非常、真正、确实、其实、显然） | 空强调。参见 phrases.md。 |
| 四字成语连续堆砌 | 装饰性填充，没有信息。参见 phrases.md。 |
| 大词代替小词（"审视"代替"看"，"践行"代替"做"） | 刻意拔高。用简单直接的词。 |

## 公式→人话翻译

AI最擅长的手法：给一个公式，然后紧跟着用人话把公式"翻译"一遍。两条信息说的是同一件事，读者被迫读两遍。

| 模式 | 问题 |
|------|------|
| 给出公式 $E=mc^2$，然后说"也就是说，能量等于质量乘以光速的平方" | 同一件事说了两遍 |
| 给出算法步骤，然后用自然语言再解释一遍步骤做了什么 | 重复 |
| 给出定理陈述，然后说"直观理解：这个定理告诉我们..." | 元评论 |

**替代：** 信任读者能读懂公式或技术描述。如果公式不够清楚，改进公式本身或补充符号说明，而不是整段重述。如果人话解释就够了，那公式可能是多余的。二选一，不要两个都给。

**例外：** 第一次引入非标准符号或记号时，用简短括号说明是可以的。"令 $\tau$ 为弛豫时间（即谱隙的倒数）"是定义，不是翻译。

## 双语对译

"中文词（English Term）"结构。AI习惯给每个术语配上中英文对照，像词典词条。

| 模式 | 问题 |
|------|------|
| "影子重叠（Shadow Overlap）" | 没人说"影子重叠"，直接用 Shadow Overlap |
| "局域化量子性（Localizable Quantumness）" | 强行造的中文译名，没人这么叫 |
| "量子态断层扫描（Quantum State Tomography）" | QST 已是通用的缩写 |
| "神经量子态（Neural Quantum State）" | NQS 即可 |
| "量子魔力（Quantum Magic）" | 文献中两种说法都有，选一个用到底 |

**规则：**
- 第一次出现时可以标注一次："Shadow Overlap（影子重叠协议）"或反过来。
- 之后全文统一用一个。不要每次出现都带括号。
- 没有通行中文译名的术语，直接用英文。不要强行翻译。
- 已有通用缩写的（QST、NQS、BRM），用缩写。

## 格式痕迹

痕迹不只在句子层面，也在排版层面。

| 模式 | 问题 |
|------|------|
| 加粗滥用（每段都有**重点**） | 加粗越多，重点越少。全文加粗不超过两三处。 |
| 内联标题列表："**背景：**...**方法：**...**结果：**..." | 假装结构化。真需要结构就用真正的标题，不需要就写成连贯段落。 |
| emoji当装饰："🚀 让我们开始吧" | 正文不用emoji。 |
| 一句话一段的碎片化排版 | 合并成有呼吸感的段落。 |
| 把论述拆成编号段落（"1. 系统化视角 2. 跨学科整合……"） | 假装结构化。列表留给真正的并列项，论述写成段落。 |
| Markdown残留（段间水平线、错乱的代码块格式） | 生成痕迹。清理格式。 |

**改文件时：** 只改散文部分。代码块、frontmatter、链接目标、表格数据不动。说明文、指令文档里承担扫读功能的加粗引导词，保留两三处没问题；清零和滥用一样是痕迹。

## 无效指标

下面这些情况单独出现不构成AI痕迹，不要改：

- 语法干净、没有错别字。人也写得干净。
- 正式或书面的语域。公文、论文本来就该正式。
- 单独一个过渡词（"但是"、"因此"、"所以"）。
- 单独一个四字成语、单独一个被动句。
- 同义词轮换（为避免重复而换说法）。这是人类写作习惯。
- 偶尔一个破折号或分号。
- 长句。人也会写长句。

**强度分级：** 强信号（"不是...而是..."、排比泛滥、开头套话、空泛升华、模糊归因）见一次就改；弱信号（成语、被动句、过渡词、破折号）只在聚集出现、形成模式时才改。拿不准时不改，漏掉一处痕迹的代价远小于把正常表达改坏。
